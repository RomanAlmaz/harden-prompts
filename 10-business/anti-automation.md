# Автоматические злоупотребления

Регистрация, отзывы, бронирование и перебор форм дешевеют, если сервер принимает безлимитные одинаковые действия. Капча одна не лечит: её обходят там, где действие всё ещё бесплатное и без лимита.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Нет лимита на создание объектов | База и почта забиваются |
| Капча проверяется только в браузере | API её не видит |
| Капча-секрет на клиенте | Кто угодно отмечает «я человек» |
| Один контроль на всех, включая оплату и вход | Входу не хватает отдельного лимита, а обычному API больно |
| Сбор десятков признаков браузера без нужды | Лишние данные людей, слабая польза |

## Сделать

1. Серверный лимит на конкретное действие. См. `rate-limit.md`.
2. Если капча нужна: проверка секрета на сервере, токен одноразовый, капча не стоит вместо права и не стоит на каждом безопасном чтении.
3. Дорогие действия (письмо, SMS, бронь последней единицы) имеют отдельный потолок и идемпотентность.
4. Не тащить тотальный фингерпринтинг. Если включаешь риск-оценку поставщика, запиши какие данные уходят и зачем.
5. Ответ честный и одинаковый, без подсказок, как обойти.

## Промпт

```text
Найди действия, которые можно повторять бесплатно и вредно: регистрация, отзыв, приглашение, бронь, рассылка.

Поставь серверный лимит. Капчу, если она есть, проверяй на сервере и не считай её единственной защитой.
Не добавляй тотальный сбор отпечатков браузера.
Не описывай обход капчи.
```

## Готово, когда

- [ ] Массовое создание ограничено на сервере
- [ ] Секрет капчи не в клиенте
- [ ] Капча не заменяет проверку прав
- [ ] Нет нового тотального фингерпринтинга
