# Сообщения между окнами

`postMessage` доставляет данные другому окну. Если принимающая сторона не проверяет origin отправителя, любое окно может прислать команду. Если отправитель ставит цель `*`, сообщение уходит не туда.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Обработчик не смотрит `event.origin` | Чужое окно шлёт команду оплаты, входа или навигации |
| Цель сообщения `*` | Данные уходят окну, которое оказалось на этом месте |
| В сообщении секрет или токен | Его получает не тот origin |
| Из сообщения собирают HTML или `eval` | Текст сообщения становится кодом. См. `06-input/xss.md` |

## Сделать

1. В обработчике сравнивать `event.origin` с точным списком. Не сравнивать подстрокой и не доверять `event.source` без origin.
2. Отправлять на точный origin, не на `*`, если в сообщении есть что-то кроме безвредного сигнала «высота виджета».
3. Не класть в сообщение токены и персональные данные. Команду всё равно проверять на сервере.
4. Данные сообщения не вставлять в HTML и не исполнять.
5. Виджету на чужом сайте отдавать отдельный ограниченный протокол, не доступ к сессии родителя.

## Промпт

```text
Найди postMessage, window.opener и обмен с iframe.

Приём: точное сравнение event.origin со списком. Отправка: конкретный origin, не звезда, если в сообщении не только безвредный сигнал размера.
Не передавай токены. Не вставляй данные сообщения в HTML и не исполняй их.
Команду, которая меняет данные, подтверждай на сервере.

Не пиши чужое окно, которое шлёт команды. Если postMessage нет - пропусти.
```

## Готово, когда

- [ ] Origin отправителя проверяется точно
- [ ] Секреты не уходят в `*`
- [ ] Текст сообщения не становится HTML или кодом
