# Кэш ответов

Общий кэш CDN и прокси может запомнить личный ответ и отдать его следующему человеку. Или запомнить ответ, собранный из заголовка, которого нет в ключе кэша.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Личная страница кэшируется как общая | Следующий посетитель видит чужой кабинет |
| Ответ меняется от заголовка, а ключ кэша этот заголовок не включает | В кэш попадает чужая версия страницы |
| Неаутентифицированный запрос кэширует ответ с данными сессии | Кэш становится копией сессии |
| Ошибка с токеном в теле запоминается | Токен живёт в кэше |

## Сделать

1. Ответы с сессией, почтой, заказом и админкой: `Cache-Control: no-store`. См. также `security-headers.md`.
2. Публичный кэш только для ответов, которые одинаковы для всех. Ключ кэша должен включать всё, от чего зависит тело: путь, важные query, сжатие, язык, если язык меняет тело.
3. Не строить тело из заголовков вроде хоста и переопределения схемы, если эти заголовки не входят в ключ и не нормализованы доверенным прокси.
4. Аутентифицированный и анонимный ответы не складывать в один ключ.
5. Не класть токены в URL, которые могут осесть в кэше и в access-log.

## Промпт

```text
Проверь заголовки кэша у личных и публичных ответов.

Личные ответы пометь no-store. Публичный кэш разрешай только там, где тело не зависит от пользователя.
Если тело зависит от заголовка, этот заголовок должен входить в ключ кэша или заголовок надо игнорировать.
Не кэшируй ответы с сессией вместе с анонимными.

Не описывай отравление кэша и не меняй боевой CDN из этой задачи, если его нет в репозитории: тогда оставь пункт человеку.
```

## Готово, когда

- [ ] Личные ответы не кэшируются общим кэшем
- [ ] Ключ публичного кэша покрывает то, от чего зависит тело
- [ ] Токены не стоят в кэшируемых URL
