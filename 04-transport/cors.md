# CORS

CORS решает, какой чужой сайт может прочитать ответ браузером. Звёздочка вместе с учётными данными открывает API любому сайту, где у человека есть сессия.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| `Access-Control-Allow-Origin: *` вместе с cookie | Чужой сайт читает ответ, который браузер отправил с cookie человека |
| Origin отражается как есть | Любой сайт записывает себя в разрешённые |
| Разрешён `null` | Нестандартные документы проходят проверку |
| Слишком широкий список методов и заголовков | Лишнее становится доступно кросс-сайтом |
| Проверка origin по подстроке `allowed.com` | Проходит `allowed.com.evil.example` |
| Серверные вызовы путают с CORS | CORS не защищает сервер от сервера, его ошибочно считают авторизацией |

## Сделать

1. Белый список точных origin. Сравнение строки целиком, не «содержит».
2. Если нужен доступ с cookie или `Authorization`, origin не может быть `*`. Заголовок `Allow-Credentials: true` только вместе с конкретным origin.
3. Не отражать произвольный `Origin`. Не разрешать `null`, пока нет отдельной доказанной нужды.
4. Методы и заголовки - только те, что API ждёт.
5. CORS не заменяет проверку прав на объекте. Даже свой фронт получает только свои данные.
6. Варьировать origin в ответе - значит варьировать кэш: `Vary: Origin`.

## Промпт

```text
Проверь CORS. Разрешай чтение ответов только точным origin из конфига.

Не отражай присланный Origin. Не сочетай звёздочку с учётными данными. Не разрешай null без отдельной причины.
Список методов и заголовков сузь. Добавь Vary: Origin, если origin в ответе меняется.
Не считай CORS авторизацией: права на данные проверь отдельно.

Не пиши чужой сайт, который читает API. Если CORS не нужен, потому что фронт и API на одном origin, - не включай широкий CORS «на будущее».
```

## Готово, когда

- [ ] Origin не отражается зеркалом
- [ ] Нет пары «звёздочка + credentials»
- [ ] Список origin точный
- [ ] CORS не стоит вместо проверки прав
