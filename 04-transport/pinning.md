# Привязка сертификата

Привязка решает, какому ключу сервера верит клиент сверх обычных центров сертификации. Ошибочная привязка к листовому сертификату без запасного ключа ломает приложение в день ротации и не чинится у тех, кто не обновил клиент.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Привязан сам листовой сертификат, а не ключ | Плановая смена сертификата отключает клиентов |
| Нет запасного ключа | Потеря основного ключа выключает всех |
| Старый HPKP в заголовках браузера | Браузер запоминает привязку надолго, ошибка почти необратима |
| Привязка отключена «в отладке» и эта сборка ушла в магазин | Клиент принимает любой сертификат |
| Проверка сертификата выключена вместо честной привязки | Канал больше не проверяется |

## Сделать

1. Обычный сайт в браузере: HSTS и нормальный сертификат, не HPKP. Привязку в браузерных заголовках не включать.
2. Мобильный или нативный клиент: если привязка нужна, привязывать открытый ключ (SPKI), держать запасной ключ, иметь выпуск приложения раньше смены ключа.
3. Не отключать обычную проверку имени хоста и срока.
4. Отладочный флаг «верить всем» не должен попасть в боевую сборку.
5. Если привязки нет и клиент только браузерный, файл не требует нового кода: так и написать.

## Промпт

```text
Проверь привязку сертификатов и отключение проверки TLS.

В браузерном сайте не включай HPKP. Оставь обычную проверку сертификата и HSTS по файлу tls.
В мобильном клиенте, если привязка уже есть, привязывай ключ, а не листовой сертификат, и проверь, что есть запасной ключ и путь обновления.
Убери флаг, который отключает проверку сертификата, из боевой сборки.

Не пиши обход проверки и не ставь боевые пины наугад.
```

## Готово, когда

- [ ] HPKP не включён для обычного сайта
- [ ] Боевая сборка не отключает проверку сертификата
- [ ] Если пин есть, он на ключ и со запасным ключом
