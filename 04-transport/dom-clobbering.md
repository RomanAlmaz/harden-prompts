# Подмена глобальных имён через разметку

Браузер кладёт элементы с `id` и `name` в глобальные свойства документа. Если код читает «настройку» из глобального имени, чужая разметка подменяет эту настройку.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Конфиг читают из `window.какоеТоИмя` или `document.какоеТоИмя`, которое может создать HTML | Разметка задаёт адрес скрипта, флаг или URL |
| HTML пользователя вставляется как разметка | Вместе с текстом появляются элементы с нужными id |
| Виджет ищет настройку в DOM, а не в своём объекте | Настройка живёт там, куда пишет и страница |

## Сделать

1. Настройки, URL и флаги хранить в своём объекте скрипта или в JSON, который разобран один раз. Не читать их из свойств `document` и `window`, совпадающих с id элементов.
2. Пользовательский HTML пропускать через санитайзер. См. `06-input/xss.md`. Выкидывать или переименовывать `id` и `name`, если они не нужны.
3. Не вставлять непроверенный HTML через `innerHTML`.
4. CSP оставить вторым слоем. См. `csp.md`.

## Промпт

```text
Найди код, который берёт URL, флаг или имя скрипта из глобального свойства window или document.

Перенеси такие настройки в свой объект или в один разобранный JSON.
Пользовательский HTML пропускай через санитайзер и не давай ему задавать id, от которых зависит логика.
Не вставляй сырой HTML через innerHTML.

Не добавляй примеры разметки, которая подменяет глобальные имена.
```

## Готово, когда

- [ ] Конфиг не читается из id элемента
- [ ] Пользовательский HTML не задаёт рабочие id логики
- [ ] Нет сырого innerHTML для чужих данных
