# HTTPS и TLS

Без шифрования канала пароль, cookie и платёж читаются в той сети, где сидит человек. Перехват здесь закрывают протоколом и настройкой сервера, а не советом «не пользоваться чужим Wi-Fi».

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Сайт открывается по HTTP | Логин, сессия и оплата видны в сети |
| Смешанный контент | Часть страницы тянется без шифрования, скрипт можно подменить по пути |
| Старые протоколы SSL и TLS 1.0/1.1 | Канал слабее, чем ждут клиенты |
| Сертификат не проверяют во внутренних вызовах | Сервис принимает чужой узел |
| Редирект на HTTPS забывает выставить флаг `Secure` до редиректа | Cookie успевает уйти открытым текстом |
| HSTS нет | Браузер хоть раз можно поймать на первом HTTP |
| Секреты в ссылках `http://` внутри писем | Человек приходит сразу в открытый канал |

## Сделать

1. Весь внешний трафик людей и вебхуков - TLS. HTTP только режет на HTTPS, ничего секретного по HTTP не отвечает, cookie по HTTP не ставит.
2. HSTS на боевом домене после проверки, что HTTPS стабилен. `includeSubDomains` - только если все поддомены правда говорят по HTTPS. `preload` - отдельное решение человека.
3. На новых сервисах не включать SSL, TLS 1.0 и TLS 1.1. Ориентир - TLS 1.2+ с современными наборами, лучше TLS 1.3, где платформа умеет. Конкретную строку шифров брать из актуального Transport Layer Security Cheat Sheet, не копировать старый блог.
4. Сертификат от нормального CA, срок и имя хоста совпадают. Автообновление. Не отключать проверку сертификата у HTTP-клиентов (`rejectUnauthorized`, аналог `curl -k` в коде).
5. С картинок, скриптов и API убрать абсолютные `http://`.
6. Внутренние вызовы между сервисами тоже шифровать или держать в сети, которая это заменяет осознанно. «Всё в одной VPC, значит можно HTTP без аутентификации» - не оставлять молча: хотя бы аутентификация сервиса и запись решения.
7. Не класть токены в URL: они оседают в логах прокси.

## Промпт

```text
Переведи внешний доступ на HTTPS и запрети тихое отключение проверки сертификатов.

Сделай:
- HTTP не отдаёт секреты и не ставит сессию, только редирект на HTTPS либо пустой отказ;
- ссылки приложения, cookie Secure и вебхуки рассчитаны на HTTPS;
- HSTS подготовь для прода, includeSubDomains не включай вслепую;
- не используй SSL и TLS 1.0/1.1 для новых настроек;
- HTTP-клиенты в коде проверяют сертификат, флага «не проверять» в проде нет;
- токены не стоят в query.

Не пиши перехват трафика и не ослабляй TLS ради локальной отладки в коде прода. Локальные исключения пометь явно и не копируй их в прод. Если сертификат выпускает инфраструктура вне репозитория - перечисли, что должен сделать человек.
```

## Готово, когда

- [ ] Секреты не ходят по HTTP
- [ ] Клиенты не отключают проверку сертификата
- [ ] HSTS описан или включён для прода
- [ ] Устаревшие протоколы не включены новой конфигурацией
- [ ] Токенов нет в URL
