# Вебхуки оплаты

Серверное уведомление шлюза подтверждает деньги только если магазин проверил, что его прислал шлюз, и провёл заказ один раз. Тело запроса без проверки - просто JSON от кого угодно.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Нет проверки подписи | Любой POST помечает заказ оплаченным |
| Подпись считают после того, как фреймворк уже поменял тело | Подпись никогда не сходится, её отключают «на время» |
| Секрет подписи в репозитории | Подпись перестаёт быть секретом |
| Повтор доставки создаёт вторую отгрузку | Шлюз присылает то же событие ещё раз, магазин отгружает снова |
| Вебхук опоздал, и его выкидывают только из-за срока корзины | Успешный платёж теряют или, наоборот, позже принимают без сверки |
| В лог пишут сырое тело и заголовки | Там секрет и данные плательщика |
| По ответу вебхука виден внутренний стек | Лишнее раскрытие устройства оплаты |

## Сделать

1. Проверять подпись по сырому телу, как требует документация шлюза. Свой секрет, сравнение без утечки по времени, если сравниваешь сам, лучше функцией библиотеки.
2. Секрет вне git, разный для теста и прода.
3. Отклонять уведомление без годной подписи. Не отгружать.
4. Идемпотентность: ключ события хранить. Повтор того же события не отгружает снова и отвечает успехом, чтобы шлюз не ретраил вечно.
5. После подписи всё равно сверить у API шлюза текущий статус, сумму, валюту и id заказа. Уведомление может прийти не по порядку.
6. Просроченную корзину не отгружать вслепую. Позднее уведомление обработать: сверить платёж и либо завершить заказ, либо запустить возврат по правилам продукта. Не молча помечать оплаченным.
7. Ответ вебхука короткий, без стека и без эха секрета. Логи: id события, итог проверки, id заказа. Не сырое тело целиком.
8. Эндпоинт не требует сессии покупателя. Нельзя, чтобы отсутствие сессии отключало проверку подписи.

## Промпт

```text
Усиль приём платёжных вебхуков.

Подпись проверяй по сырым байтам тела до любой перепаковки JSON. Секрет не в коде.
Без годной подписи не меняй заказ.
Одно и то же событие обрабатывай один раз и на повтор отвечай успехом без второй отгрузки.
После подписи сверь статус, сумму, валюту и id заказа запросом к API шлюза.
Позднее уведомление не игнорируй только из-за таймера корзины и не оплачивай заказ без сверки.
В лог не пиши секрет, сырое тело и данные карты. Наружу не отдавай стек.

Не пиши подделку подписи. Если вебхука нет - пропусти.
```

## Готово, когда

- [ ] Подпись обязательна и считается от сырого тела
- [ ] Повтор события не удваивает отгрузку
- [ ] Статус дополнительно сверен с API шлюза
- [ ] Секрет и карта не попадают в лог
