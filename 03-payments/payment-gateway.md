# Интеграция платёжного шлюза

Шлюз забирает карту у магазина, только если магазин не видит карту и не верит браузеру на слово. Ключ API в фронтенде равен ключу в открытом доступе.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Секретный ключ в JS, мобильном приложении или git | Ключом создают и подтверждают чужие операции |
| Магазин сам собирает номер карты на своём сервере без нужды | Магазин попадает в полную область PCI и хранит то, что не должен |
| Возврат покупателя на `success_url` считается оплатой | URL успеха открывают без платежа |
| Не сверяются id, сумма и валюта | Платёж за другой заказ или другую сумму закрывает этот |
| Тестовый ключ работает на проде | Платежи «успешны» без денег |
| Нет сверки подписи у серверного уведомления | Статус присылает кто угодно |

## Сделать

1. Предпочесть hosted fields, виджет или редирект на страницу шлюза, чтобы номер карты не проходил через сервер магазина. Не сохранять PAN, CVV, полную дорожку и PIN. См. `cardholder-data.md`.
2. Секретный ключ только на сервере, в хранилище секретов. В браузер можно отдавать только публичный ключ, если шлюз так устроен.
3. Создание платежа - сервер-сервер. В метаданных свой id заказа. Сумма и валюта из пересчёта заказа.
4. `success_url` показывает страницу «проверяем оплату». Факт оплаты - запрос магазина к API шлюза или проверенное серверное уведомление.
5. Перед отгрузкой совпали: id платежа, id заказа, сумма, валюта, статус «успех» в терминологии этого шлюза. Чужой статус вроде pending не отгружает.
6. Боевой и тестовый ключи разведены по средам. Тестовый ключ на проде не принимается.
7. Ошибки шлюза не отдают сырой ответ с ключом и данными плательщика наружу.

## Промпт

```text
Проверь интеграцию платёжного шлюза. Не подключай боевой ключ и не логируй его.

Сделай:
- секретный ключ только на сервере и вне git;
- карту не проводить через свой сервер, если шлюз умеет hosted-форму или виджет;
- платёж создаёт сервер, сумма из серверного заказа;
- страница успешного возврата не ставит статус оплачен;
- перед выдачей товара сервер сверяет у шлюза id, сумму, валюту и успешный статус;
- тест и прод не путают ключи.

Если шлюза в проекте нет - не выбирай вендора сам, опиши дыры текущей оплаты и остановись.
Не пиши обход подписи шлюза.
```

## Готово, когда

- [ ] Секрет шлюза не в клиенте и не в git
- [ ] Карта не сохраняется магазином
- [ ] Успешный редирект сам по себе не отгружает
- [ ] Сумма и id сверяются со шлюзом
- [ ] Тестовый ключ не годится для прода
