# Подтверждение дорогой операции

Обычная сессия не должна молча отправить деньги, сменить карту выплаты или подтвердить возврат на другой счёт. Подтверждение привязано к конкретной операции и живёт один раз.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Один код MFA на всю сессию разрешает любые платежи | Код, спрошенный утром, тратит деньги вечером |
| Сумма и получатель не входят в то, что человек подтвердил | Подтвердили 10, ушло 10 000 или другому получателю |
| Проверку можно выключить параметром запроса | Клиент шлёт «authorization=skip» |
| Один код принимают на несколько операций | Повтор того же подтверждения |
| Решение принимает браузер | Сервер верит флагу |
| Нет срока у подтверждения | Старое согласие проводят позже |

## Сделать

1. Сервер, не клиент, решает, какие действия требуют шаг вверх: выплата, смена реквизитов, крупный перевод, возврат не на исходный платёж, смена почты.
2. Человек подтверждает конкретные поля: сумма, валюта, получатель, id операции. После подтверждения эти поля не меняются. Изменились - подтверждение заново.
3. Код или подпись WebAuthn одноразовые, с коротким сроком, помечаются использованными атомарно до проведения операции.
4. Нельзя отключить шаг параметром, ролью из токена клиента или «внутренним» заголовком, который может прислать браузер.
5. Повтор запроса с тем же ключом идемпотентности не проводит деньги второй раз.
6. Неудачные подтверждения ограничены по частоте.
7. Журнал: id операции, итог, без самого кода и без полных реквизитов карты.

## Промпт

```text
Найди операции, которые двигают деньги или реквизиты выплат. Требуй серверное подтверждение конкретной операции.

Подтверждение содержит сумму, валюту, получателя и id. Чужой параметр не отключает проверку.
Код или WebAuthn-подтверждение одноразовые и короткие. Повторно их не принимать.
Проведение платежа идемпотентно.
Не логируй код подтверждения.

Не описывай, как перехватить код. Если таких операций нет - пропусти.
```

## Готово, когда

- [ ] Дорогие действия не идут одной старой сессией
- [ ] Подтверждение привязано к сумме и получателю
- [ ] Клиент не выключает проверку
- [ ] Один код не проводит две операции
