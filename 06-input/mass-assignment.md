# Лишние поля объекта

Если тело JSON целиком заливается в модель, человек присылает поля, которых нет в форме: роль, подтверждение почты, цену, чужой `user_id`.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| `update(request.body)` без списка | Меняются скрытые поля |
| Один и тот же тип на создание админа и профиль пользователя | Пользователь задаёт себе права админа |
| PATCH сливает объект глубоко | Вложенным полем меняют владельца |
| Скрытые поля формы всё равно принимаются сервером | Прямой запрос их задаёт |
| Импорт CSV с лишней колонкой | Колонка становится полем модели |

## Сделать

1. Отдельная схема входа на каждое действие. В модели записи только перечисленные поля.
2. Поля прав, владельца, баланса, флагов верификации и статуса заказа в эту схему не входят. Их меняют отдельные команды со своими проверками.
3. Вложенные объекты тоже по схеме, без рекурсивного «прими всё».
4. Тест: лишнее поле в запросе не меняет запись. Это тест отказа, не набор обходов.
5. Админская схема не переиспользуется как пользовательская.

## Промпт

```text
Запрети запись модели напрямую из тела запроса.

Для каждого обновления сделай явную схему полей. Роль, владелец, баланс, флаги подтверждения и статус платежа пусть меняются только отдельными командами с проверкой прав.
Покрой тестом, что лишнее поле игнорируется или отклоняется и не меняет эти колонки.

Не описывай набор полей для захвата прав как инструкцию. Если так уже пишет ORM, включи её защиту от массового присваивания, не выключай её.
```

## Готово, когда

- [ ] Тело запроса не копируется в модель целиком
- [ ] Права и деньги не входят в обычную схему профиля
- [ ] Админская и пользовательская схемы разные
- [ ] Лишнее поле не меняет запись
