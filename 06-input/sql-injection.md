# Запросы к SQL

Склейка текста запроса с вводом человека позволяет этому вводу стать командой базе. Параметр запроса оставляет ввод данными.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Строка SQL собирается конкатенацией или шаблоном с пользовательским куском | Ввод меняет смысл запроса |
| Параметризован только `WHERE`, а имя столбца сортировки вклеено как есть | Сортировка и фильтр становятся командой |
| Динамический `IN (...)` собран склейкой | Список значений выходит из роли данных |
| Ошибка базы с текстом запроса уходит клиенту | Видно схему и кусок запроса |
| Учётная запись приложения - владелец базы | Ошибка в запросе сразу читает и меняет всё |
| ORM обходят сырым `raw` | Обход прячется в одном месте |

## Сделать

1. Все значения - параметры подготовленного запроса или API ORM, который параметризует сам. Не склеивать ввод в строку SQL.
2. Имена таблиц, столбцов и направление сортировки не параметризуются драйвером. Их брать только из белого списка в коде.
3. Поиск по шаблону: экранировать служебные символы шаблона либо пользоваться безопасным API. Не отключать параметризацию ради LIKE.
4. Учётная запись приложения: только нужные таблицы и действия. Не суперпользователь. Отдельная учётка для миграций.
5. Ошибки базы не отдавать клиенту. В лог - id запроса, не пароль из текста.
6. Найти `raw`, `execute(` со строкой, интерполяцию f-string/template в SQL и убрать ввод оттуда.

## Промпт

```text
Убери склейку пользовательского ввода с текстом SQL.

Значения передавай только параметрами драйвера или ORM. Имена столбцов сортировки и фильтров закрой белым списком.
Найди сырые запросы и проверь их так же.
Учётка приложения не должна быть владельцем сервера базы: сузь права, если это видно в миграциях и конфиге репозитория. Боевой пароль базы не трогай и не копируй.
Ошибки SQL не возвращай клиенту.

Не добавляй примеры вредоносных запросов и не выполняй запросы к боевой базе ради проверки.
```

## Готово, когда

- [ ] Значения в запросах параметризованы
- [ ] Сортировка и имена полей идут из белого списка
- [ ] Сырой SQL найден и приведён к тому же правилу
- [ ] Клиент не видит текст ошибки базы
