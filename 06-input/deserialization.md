# Разбор сериализованных объектов

Форматы, которые умеют восстановить объект с поведением, исполняют данные как код. JSON с фиксированной схемой только данные. Родной pickle, небезопасный YAML и бинарные родные графы объектов - нет.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| `pickle`, `unserialize`, `BinaryFormatter`, родной YAML `load` на данных от пользователя | Данные становятся вызовом кода |
| Тип объекта приходит внутри сообщения | Разбор создаёт не тот класс |
| Сжатый или вложенный формат без лимита | Память кончается на маленьком запросе |
| Секретный токен - это сериализованный объект без подписи | Объект меняют и сервер его принимает |

## Сделать

1. На границе системы принимать JSON или другой формат данных со схемой. Не принимать родную сериализацию языка от клиента и из очереди, если очередь может писать недоверенный отправитель.
2. YAML только безопасным загрузчиком. XML - без внешних сущностей и без разбора типов в объекты, подробности в `xxe.md`. Лимит размера обязателен.
3. Если подписанный билет ещё содержит сериализованный вид, проверять подпись до разбора и разбирать в фиксированный тип, не в произвольный класс.
4. Лимит размера и глубины до разбора.
5. Найти опасные функции разбора по проекту и заменить. Не оставлять «только для админки», если туда попадает внешний файл.

## Промпт

```text
Найди разбор данных, который может создавать объекты с поведением: pickle и аналоги, небезопасный YAML, родные бинарные форматтеры, XML с внешними сущностями.

Замени их на формат данных со схемой. Подпись проверяй до разбора. Поставь лимит размера и глубины.
Не оставляй опасный разбор за комментарием «внутреннее».

Не добавляй вредоносные примеры объектов и не исполняй неизвестные файлы из тикетов.
```

## Готово, когда

- [ ] Внешний вход не кормит родной десериализатор объектов
- [ ] YAML и XML разбираются в безопасном режиме
- [ ] Есть лимит размера
- [ ] Подпись билета проверяется до разбора
