# Запросы XPath

XPath для XML - тот же риск, что склейка SQL: кусок ввода становится частью запроса и меняет, какие узлы вернутся.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Выражение XPath собрано из строки пользователя | Запрос читает не те узлы |
| Имя элемента или атрибута приходит снаружи | Запрос выходит из ожидаемой ветки документа |
| Ошибка XPath возвращает выражение | Видно структуру документа |

## Сделать

1. Не склеивать ввод с текстом XPath. Передавать значение параметром, если библиотека умеет, либо сравнивать уже выбранные узлы в коде.
2. Имена осей, элементов и атрибутов - из белого списка.
3. Документ, по которому ищут, не должен содержать секреты сверх того, что этот пользователь и так может получить.
4. Ошибку выражения не отдавать клиенту.

## Промпт

```text
Найди сборку XPath из пользовательского ввода.

Значения не склеивай с выражением. Имена узлов бери из белого списка. Ошибку XPath наружу не отдавай.
Если XPath нет - пропусти. Не добавляй примеры выражений.
```

## Готово, когда

- [ ] Ввод не склеивается с текстом XPath
- [ ] Имена узлов из белого списка
- [ ] Ошибка выражения не уходит клиенту
