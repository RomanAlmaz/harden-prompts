# NoSQL, LDAP и прототип объекта

Там, где запрос - это не SQL, а объект или фильтр каталога, ввод всё равно нельзя склеивать в команду. Отдельно: слияние JSON не должно менять прототип объектов языка.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Фильтр Mongo и аналогов собирается из тела запроса | Операторы запроса приходят от клиента |
| Фильтр LDAP склеен из строки входа | Запрос к каталогу меняет смысл |
| `merge` объекта с JSON без запрета ключей прототипа | Меняется поведение всех объектов процесса |
| Рекурсивное копирование конфига из запроса | Человек переписывает внутренние флаги |

## Сделать

1. Запросы к документной базе строить в коде. От клиента принимать поля данных, не операторы запроса. Отбрасывать ключи, которые начинаются со знака оператора, если драйвер так устроен.
2. LDAP: экранирование через API библиотеки или параметры, не склейка фильтра.
3. Не делать глубокое слияние недоверенного JSON в конфиг и в объект с прототипом. Разрешать только перечисленные ключи. Включить защиту языка или фреймворка от загрязнения прототипа, если она есть.
4. Карты и объекты из запроса не использовать как источник ключей `__proto__`, `prototype`, `constructor`.

## Промпт

```text
Проверь документные запросы, LDAP-фильтры и глубокие merge JSON.

Клиент не должен задавать операторы запроса. Фильтры строй в коде из отдельных полей.
LDAP не склеивай строкой. Слияние объектов ограничь белым списком ключей и запрети ключи прототипа.
Не добавляй примеры вредоносных операторов.
```

## Готово, когда

- [ ] Операторы документной базы не приходят из тела запроса
- [ ] LDAP-фильтр не собран склейкой
- [ ] Недоверенный JSON не сливается в прототип или конфиг
