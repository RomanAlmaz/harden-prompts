# Шаблоны на сервере

Шаблон - это код представления. Если в него попадает строка человека как синтаксис шаблона, сервер исполняет чужой шаблон с правами приложения.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Письмо, отчёт или страница собираются шаблоном из строки пользователя | Строка становится командой шаблонизатора |
| Песочница выключена у движка, который её имеет | Шаблону видны файлы и объекты приложения |
| Имя шаблона приходит из параметра | Открывается не тот файл. См. `path-traversal.md` |
| Ошибка шаблона отдаёт исходник и пути | Наружу видно устройство сервера |

## Сделать

1. Шаблоны писем, страниц и отчётов - файлы в репозитории. Данные человека передавать аргументами, не склеивать со строкой шаблона.
2. Если продукт правда даёт людям править шаблон, это отдельное право, не общий профиль. Движок без доступа к файлам, среде и произвольным объектам. Лучше безопасный поднабор, не полный язык шаблонов.
3. Имя шаблона выбирать из белого списка id.
4. Ошибки рендера не возвращать клиенту. См. `09-data/errors.md`.
5. Найти вызовы render со строкой из запроса, из базы писем и из темы сообщения.

## Промпт

```text
Найди серверные шаблоны: страницы, письма, отчёты, PDF.

Данные пользователя передавай аргументами в фиксированный шаблон. Не рендерь строку запроса или тему письма как шаблон.
Имя шаблона бери из белого списка. Если людям нужен свой текст письма, не давай им полный язык шаблонов приложения.
Ошибки рендера наружу не отдавай.

Не добавляй примеры синтаксиса шаблонов и не включай шаблонизатор без ограничений ради проверки.
```

## Готово, когда

- [ ] Строка пользователя не является шаблоном
- [ ] Имя шаблона из белого списка
- [ ] Пользовательский текст письма не имеет прав кода приложения
- [ ] Ошибка шаблона не раскрывает пути
