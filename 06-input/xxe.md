# Разбор XML

XML умеет подтягивать внешние и внутренние сущности. Для данных приложения это не нужно. Включённый разбор сущностей заставляет сервер читать свои файлы и ходить по сети.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Парсер резолвит внешние сущности и DTD | XML из запроса читает локальные файлы или зовёт чужой адрес |
| Раскрытие сущностей без лимита | Маленький документ разворачивается в огромный и забивает память |
| XSLT или внешняя схема берутся из документа | Исполняется не тот набор правил |
| Тот же парсер у SAML, SOAP, SVG и офисных файлов | Дыра не в одном «XML API», а во всех импортах |

## Сделать

1. Для новых API предпочесть JSON. XML оставить только там, где формат задан протоколом.
2. В парсере выключить DTD, внешние сущности и подгрузку внешних схем. Лимит размера и глубины.
3. Проверить все зависимости: SOAP, SAML, загрузка SVG, DOCX, парсеры фидов.
4. Не отдавать клиенту текст ошибки парсера.
5. Не ходить по адресам из документа. Если адрес нужен продукту, это уже `ssrf.md`, не побочный эффект XML.

## Промпт

```text
Найди разбор XML, SOAP, SVG, офисных файлов и SAML.

Выключи DTD и внешние сущности. Поставь лимит размера. Не подгружай схемы и стили по адресу из документа.
Новый обмен данными по возможности оставь на JSON.
Ошибку парсера не возвращай клиенту.

Не добавляй примеры документов с сущностями и не читай локальные файлы ради проверки.
```

## Готово, когда

- [ ] Внешние сущности и DTD выключены у всех парсеров
- [ ] Есть лимит размера XML
- [ ] Документ не инициирует сетевой запрос
- [ ] Ошибка парсера не уходит клиенту
