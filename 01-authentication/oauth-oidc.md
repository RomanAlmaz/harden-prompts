# Вход через OAuth и OpenID Connect

Чужой провайдер подтверждает личность только если код, подпись и адресат токена проверяет сервер. Неявный поток и токен в адресе браузера для новых систем не годятся.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Implicit flow или токен в fragment/query | Токен светится в истории, Referer и логах |
| Нет PKCE у публичного клиента | Чужой сайт подсовывает свой код авторизации |
| `redirect_uri` совпадает по префиксу, а не целиком | Код уходит на чужой путь |
| Нет `state` или он предсказуем | Вход завершают в браузере жертвы |
| Нет `nonce` в OIDC | Старый id_token принимают снова |
| Учётку ищут только по `sub` или по почте | Тот же `sub` у другого провайдера или смена почты склеивает чужих людей |
| Алгоритм подписи берут из заголовка токена, включая `none` | Подпись не проверяется |
| Access token считают доказательством входа и не проверяют id_token | Чужой API-токен путают с личностью |
| Секрет клиента в репозитории или в фронтенде | Клиент перестаёт быть секретным |

## Сделать

1. Вход людей: authorization code и PKCE. Для браузера и мобильного клиента PKCE обязателен, для конфиденциального клиента тоже оставляй, если библиотека умеет. Implicit и resource owner password не добавлять.
2. `redirect_uri` сравнивать с точным списком. Звёздочки и «начинается с» не использовать.
3. `state` - случайный, в сессии сервера, одноразовый. Для OIDC ещё `nonce` внутри id_token.
4. Личность: проверка id_token библиотекой. Жёстко задать допустимые `iss` и `aud`, срок `exp`, алгоритм из своего конфига, не из недоверенного заголовка.
5. Связка аккаунта: пара `iss` + `sub`. Почту провайдера не делать единственным ключом. Первая склейка с местным аккаунтом по почте - только если почта у провайдера подтверждена и человек доказал вход в местный аккаунт.
6. Секрет конфиденциального клиента - в хранилище секретов. В браузер секрет не попадает.
7. Токены провайдера не класть в `localStorage`. Держать сессию своей cookie (`02-session/session.md`) или обмен на своей стороне (BFF).
8. Выход: гасить свою сессию. Если провайдер умеет отзыв, звать и его. Не считать, что закрытая вкладка вышла из провайдера.
9. Запрашивать минимальный набор scope.

## Промпт

```text
Проверь вход через OAuth 2.0 и OpenID Connect. OpenID 2.0 не возвращай.

Оставь или введи authorization code с PKCE. Для публичного клиента PKCE обязателен, для конфиденциального тоже оставь, если библиотека умеет. Убери implicit flow и пароль пользователя, который уходит напрямую в твой сервер ради чужого токена.
Сверяй redirect_uri точным совпадением.
Проверяй state и nonce. id_token проверяй библиотекой: iss, aud, exp, подпись, алгоритм из конфига, не none и не алгоритм из запроса.
Аккаунт связывай по паре iss+sub. Не склеивай людей только по email.
Секрет клиента убери из фронтенда и репозитория.
Не храни токены провайдера в localStorage. Своя сессия - HttpOnly cookie.
Scope урежь до нужного.

Не пиши обходы подписи и подмену redirect. Если OAuth нет и не нужен - пропусти.
```

## Готово, когда

- [ ] Нет implicit flow
- [ ] Есть PKCE, точный redirect, одноразовый state
- [ ] id_token проверяется, алгоритм не берётся из запроса
- [ ] Связка аккаунта по `iss` + `sub`
- [ ] Секрет клиента не в браузере и не в git
