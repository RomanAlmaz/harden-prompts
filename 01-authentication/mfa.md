# Второй фактор

Пароль подтверждает знание. Второй фактор нужен отдельно: владение ключом или устройством. Галочка «я прошёл MFA» с клиента не считается.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Флаг MFA приходит в JSON от браузера | Вход заканчивается на пароле |
| Код TOTP не ограничен по попыткам | Код перебирают в окне действия |
| Секрет TOTP лежит открытым текстом рядом с паролем | Утечка базы снимает оба фактора |
| SMS - единственный фактор на деньги и админку | Подмена SIM забирает код |
| Один и тот же код принимают много раз | Перехваченный код повторяют |
| Коды восстановления в открытом виде и без срока годности на показ | Они становятся вечным вторым паролем |
| Вход по паролю сразу выдаёт полную сессию, код спрашивают «потом» | До кода уже есть доступ к API |

## Сделать

1. После пароля сессия неполная: нельзя звать чувствительные API, пока сервер не отметил фактор. Флаг хранится на сервере.
2. Предпочитать WebAuthn/passkey или TOTP в приложении. SMS и почта как второй фактор - слабее, для админки и выплат их не оставлять единственным вариантом. Голос и секретные вопросы не считать фактором.
3. Секрет TOTP шифровать в покое отдельным ключом из хранилища секретов. В лог и в ответ после первичной настройки не отдавать.
4. Окно TOTP узкое. Лимит попыток. Один принятый код нельзя принять снова в том же окне.
5. Коды восстановления: показать один раз, в базе хранить хеш, каждый код одноразовый, мало штук, после использования предлагать новые.
6. Включение и выключение MFA, смена устройства - только после свежего входа. Выключение не делать по ссылке из почты без повторной аутентификации.
7. Админка, смена выплаты и смена почты требуют свежий второй фактор, даже если вход был давно.
8. Не придумывать свой OTP-алгоритм.

## Промпт

```text
Добавь или почини второй фактор так, чтобы его нельзя было обойти полем запроса.

Правила:
- полная сессия выдаётся только после проверки фактора на сервере;
- приоритет: WebAuthn, затем TOTP; SMS не делать единственным фактором для админки и денег;
- секрет TOTP зашифрован в покое, не логируется;
- лимит попыток кода и запрет повторно принять тот же код;
- коды восстановления показываются один раз, в базе только хеш, каждый одноразовый;
- включение и выключение MFA требуют свежую аутентификацию;
- не писать свой криптоалгоритм.

Не пиши код перебора OTP и не описывай подмену SIM как инструкцию. Если MFA продукту не нужен - напиши, какие действия всё равно требуют step-up, и остановись на вопросе к человеку.
```

## Готово, когда

- [ ] Клиент не может сам выставить «MFA пройден»
- [ ] До успешного фактора нет полной сессии
- [ ] Секрет TOTP не лежит открытым
- [ ] Код нельзя крутить без лимита и нельзя использовать повторно
- [ ] Запасные коды хранятся как хеши
