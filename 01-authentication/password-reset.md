# Сброс и смена пароля

Сброс - второй вход. Слабый токен в письме или ответ «такой почты нет» обходят нормальный пароль.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Токен сброса короткий, предсказуемый или без срока | Ссылкой из письма входят без пароля |
| Токен лежит в базе как есть | Утечка базы даёт готовые ссылки сброса |
| Письмо содержит сам пароль или новый пароль, выбранный сервером | Пароль остаётся в почте навсегда |
| Ответ различает «почты нет» и «письмо ушло» | Учётки перечисляются |
| После смены пароля старые сессии живы | Украденная сессия не умирает |
| Ссылка сброса светится в Referer и в access-log | Токен утекает на чужие сайты и в логи |
| Секретный вопрос вроде «девичья фамилия» - единственный фактор | Ответ узнаётся из открытых данных |
| Смена пароля не просит текущий пароль или свежий вход | Чужая сессия меняет пароль и запирает хозяина |

## Сделать

1. Токен сброса: CSPRNG, не меньше 128 бит, один раз. Срок - минуты или несколько часов, не дни. В базе хранить только хеш токена.
2. Ссылка только на HTTPS. У страницы сброса: `Referrer-Policy: no-referrer`. Не логировать полный URL с токеном.
3. Ответ на запрос сброса одинаковый, есть адрес в базе или нет. Время ответа выровнять.
4. Не присылать текущий или новый пароль. Человек задаёт новый пароль сам на странице по токену.
5. Новый пароль проходит те же правила, что вход, включая блоклист утечек. Нельзя поставить текущий пароль повторно, если продукт это отличает без лишнего раскрытия.
6. После успешного сброса: погасить токен, завершить все сессии и refresh-токены учётки, потребовать новый вход.
7. Смена пароля из профиля просит текущий пароль или свежую повторную аутентификацию.
8. Лимит запросов сброса на учётку и на источник.
9. Секретные вопросы не использовать как единственную защиту. Если они уже есть - не считать их фактором, см. Choosing and Using Security Questions Cheat Sheet.
10. Токен из письма не является сессией. Им можно только задать новый пароль.

## Промпт

```text
Усиль сброс и смену пароля. Не добавляй обход существующего входа.

Найди «забыли пароль», письма, токены и смену пароля в профиле.
Сделай так:
- одноразовый токен из CSPRNG, от 128 бит, короткий TTL, в базе только хеш токена;
- одинаковый ответ, существует адрес или нет;
- письмо не содержит пароль; новый пароль задаёт человек;
- ссылка HTTPS, Referrer-Policy no-referrer, URL с токеном не пишется в лог;
- после смены погасить токен, все сессии и refresh-токены;
- смена из профиля требует текущий пароль или свежий повторный вход;
- лимит запросов сброса;
- секретные вопросы не являются единственным фактором.

Не пиши эксплойты и примеры подбора токена. Если сброса нет - пропусти.
В конце: TTL, где хранится хеш токена, какие сессии гасятся.
```

## Готово, когда

- [ ] Токен одноразовый, случайный, с коротким сроком, в базе не в открытом виде
- [ ] Нельзя понять по ответу, есть ли почта
- [ ] Старые сессии умирают после смены пароля
- [ ] Смена из профиля требует текущий секрет или свежий вход
- [ ] Токен не оседает в логах
