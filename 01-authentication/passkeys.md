# Passkeys и WebAuthn

Passkey подтверждает владение ключом. Сервер хранит открытый ключ и проверяет подпись. Закрытый ключ на сервер не приходит.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Challenge генерирует браузер или challenge многоразовый | Ответ можно повторить |
| Не проверены origin и rpId | Подпись, снятую на другом сайте, принимают здесь |
| Счётчик подписи игнорируется | Клон ключа не заметен |
| В базе нет credential id и открытого ключа, верят флагу с клиента | Любой может сказать «я прошёл WebAuthn» |
| Регистрация ключа без свежего входа | К чужой сессии привязывают свой ключ |
| Свой разбор CBOR и своя проверка подписи | Ошибка в криптографии пускает чужие утверждения |

## Сделать

1. Библиотека WebAuthn с поддержкой текущего уровня спецификации. Не проверять подпись вручную.
2. Challenge создаёт сервер, хранит у себя, живёт минуты, принимается один раз.
3. Проверять rpId, origin, тип церемонии, флаг пользовательского присутствия. Для входа в аккаунт требовать пользовательскую верификацию, если продукт обещает «это точно человек с биометрией или PIN».
4. Хранить credential id, открытый ключ, алгоритм, счётчик подписи, transports. После успешной проверки сохранять новый счётчик. Если сохранённый счётчик уже был больше нуля, а новое значение не больше его - отказать и залогировать. Счётчик 0 значит, что ключ его не ведёт: из-за нуля вход не отклонять.
5. Привязка нового ключа только в уже вошедшей сессии со свежей аутентификацией. Вход ключом ищет учётку по credential id, не по произвольному user id из браузера.
6. Удаление ключа требует свежий вход и не оставляет учётку без единого способа входа, если нет запасного.
7. Не класть assertion и credential в логи целиком.

## Промпт

```text
Если в проекте есть парольный вход для людей, подготовь или почини WebAuthn/passkey через проверенную библиотеку.

Обязательно:
- challenge только с сервера, одноразовый, с коротким сроком;
- проверка origin, rpId, типа церемонии и подписи библиотекой;
- отказ, если с клиента пришёл только флаг успеха без assertion;
- в базе credential id, public key и sign count; если сохранённый счётчик был больше нуля, а новый не больше - отклонять; ноль не считать признаком клона;
- регистрация и удаление ключа только после свежего входа;
- закрытый ключ на сервер не принимать и не хранить.

Не реализуй криптографию сам и не пиши обходы проверки подписи. Если библиотеки в стеке нет - назови подходящую и остановись до согласия человека на зависимость.
```

## Готово, когда

- [ ] Challenge одноразовый и серверный
- [ ] Подпись проверяет библиотека, origin и rpId сверяются
- [ ] Счётчик подписи проверяется
- [ ] Ключ нельзя привязать без уже доказанной сессии
