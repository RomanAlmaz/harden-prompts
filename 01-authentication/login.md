# Безопасный вход в аккаунт

Вход - место, где утекают пароль и сессия. Файл нужен, если в проекте есть форма или API входа.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Пароль идёт по голому HTTP | В общей сети трафик читается, пароль и cookie уходят целиком |
| Сессия не сменяется после входа | Идентификатор, выданный до логина, становится боевой сессией |
| Разные ответы «нет пользователя» и «неверный пароль» | Чужие учётки перечисляются |
| Нет лимита попыток | Пароли перебирают, в том числе по спискам из чужих утечек |
| Секрет сравнивается обычным равенством строк | По времени ответа иногда отличают почти верный секрет |
| Пароль или токен пишется в лог | Утечка логов равна утечке входа |
| Токен лежит в `localStorage` | Любой скрипт на странице забирает сессию |

## Сделать

1. Форма и API входа только по HTTPS.
2. Cookie сессии: `Secure`, `HttpOnly`, явный `SameSite` (`Strict`, либо `Lax`, если нужен переход по ссылке из письма). Для сессии лучше имя с префиксом `__Host-`, `Path=/`, без атрибута `Domain`.
3. После успешного входа выпустить новый id сессии и уничтожить старый. Id - из CSPRNG, не меньше 64 бит энтропии, цель 128. В хранилище по возможности писать хеш id, не сырое значение.
4. Пароль проверять библиотекой медленного хеша. Правила - в `password-storage.md`.
5. Текст и код ответа для неизвестного логина и неверного пароля - одинаковые. Для несуществующего пользователя всё равно считать фиктивный хеш, чтобы время не выдавало учётку.
6. Лимит неудачных попыток на учётку и отдельный лимит на источник. Блокировка не должна навсегда закрывать восстановление через сброс пароля. Пороги - в конфиге. В лог писать срабатывание без пароля.
7. Сверять новый и меняемый пароль со списком утёкших, не отправляя пароль целиком (k-anonymity или локальный список).
8. Длина: без MFA ориентир не короче 15 символов, с MFA - не короче 8. Потолок не ниже 64. Не обрезать молча. Не требовать смену по календарю и не требовать схему «цифра + спецсимвол», если есть длина и блоклист.
9. Не класть пароль, id сессии и refresh-токен в `localStorage` / `sessionStorage`.
10. Смена почты, пароля, выплаты и выдача прав - только после повторного входа. Стыкуется с `05-access-control/privileged-actions.md`.

## Промпт

```text
Усиль вход в аккаунт в этом репозитории. Используй штатные средства текущего фреймворка.

Найди все точки входа: сайт, API, админка, мобильный клиент.
Закрой передачу пароля без TLS, фиксацию сессии, перечисление пользователей, перебор паролей, утечку пароля в логи и в браузерное хранилище.

Сделай так:
- вход только по HTTPS;
- сессионная cookie: Secure, HttpOnly, явный SameSite (Strict, или Lax если продукту нужен вход по внешней ссылке); по возможности имя __Host-, Path=/, без Domain;
- после успешного входа новый id сессии из CSPRNG (энтропия от 64 бит, цель 128), старый id уничтожить;
- пароль проверяется только медленным хешем с солью, не SHA-256 и не открытым текстом;
- неизвестный логин и неверный пароль дают один и тот же ответ и близкое время;
- лимит попыток на учётку и отдельный лимит на источник; сброс пароля при блокировке остаётся возможным;
- сверка с блоклистом утёкших паролей без отправки полного пароля;
- минимум 8 символов при включённой MFA и 15 без неё, максимум не меньше 64, без тихого обрезания и без обязательной смены по расписанию;
- пароль, сессия и refresh-токен не попадают в localStorage и в логи.

Не пиши эксплойты и payload-ы. Не ослабляй уже стоящие проверки. Если входа нет - так и напиши.
В конце: список файлов и что осталось на человека (сертификат, лимиты на балансировщике).
```

## Готово, когда

- [ ] Нет входа по HTTP
- [ ] Сессия обновляется при логине
- [ ] Cookie сессии не читается скриптом и не уходит на HTTP
- [ ] Ответы не показывают, есть ли логин
- [ ] Есть лимит попыток на учётку
- [ ] Пароль не попадает в логи и `localStorage`
- [ ] Хеш пароля не быстрый SHA/MD5
