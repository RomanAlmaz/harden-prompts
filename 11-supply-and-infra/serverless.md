# Функции по событию

Функция в облаке запускается от события: очередь, файл, HTTP. Событие - недоверенный вход. Роль функции не должна уметь всё в аккаунте.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Роль функции администратор аккаунта | Любая ошибка в коде достаёт чужие ресурсы |
| Секрет в переменной, которая видна всем, у кого есть чтение конфигурации | Секрет расходится шире хранилища |
| Событие разбирают без схемы | Лишние поля меняют действие |
| Нет таймаута и предела памяти | Один запуск дорогой и долгий |
| В пакет функции попали тесты, `.env` и лишние зависимости | В рантайме больше кода, чем нужно |
| URL функции угадывается и не проверяет подпись события | Событие присылает кто угодно |

## Сделать

1. Роль с минимальными действиями и ресурсами. Не `*`.
2. Секреты из хранилища, не из репозитория. Если платформа показывает переменные всем разработчикам, не класть туда долгоживущие ключи без нужды.
3. Тело события проверять схемой. См. `06-input/validation.md`.
4. Таймаут, память и зарезервированный предел параллелизма на дорогих функциях.
5. В артефакт не копировать `.git`, `.env` и тестовые фикстуры с данными.
6. HTTP-функция требует ту же аутентификацию, что обычный API. Событие от очереди проверять по подписи платформы, если она есть.

## Промпт

```text
Если есть функции по событию, сузь роль и проверь событие как вход.

Убери звёздочку прав. Секреты не оставляй в коде. Схему события задай явно.
Поставь таймаут. Не упаковывай в артефакт секреты и репозиторий git.
Публичный URL функции не оставляй без той же аутентификации, что у API.

Если таких функций нет - пропусти. Не создавай облачную функцию ради файла и не применяй роли в боевой аккаунт.
```

## Готово, когда

- [ ] Роль функции не на весь аккаунт
- [ ] Секрета нет в пакете
- [ ] Событие проходит схему
- [ ] Есть таймаут
