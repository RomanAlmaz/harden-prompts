# Границы сети

Сеть уменьшает, кто вообще может постучаться. Она не заменяет вход, права и проверку сервиса. Админка и база не должны висеть рядом с публичным сайтом на том же открытом порту.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| База, очередь и панель на публичных портах | До них идут в обход приложения |
| Админский интерфейс в той же сети без отдельного доступа | Его находят рядом с сайтом |
| Всё разрешено внутри сети | Соседний сервис читает чужое |
| Управление по старому открытому протоколу без шифрования | Канал администрирования читается |

## Сделать

1. Снаружи только порты, которые нужны людям и вебхукам. База и очереди без публичного адреса.
2. Админский доступ отдельным путём, с тем же MFA, что в `05-access-control/privileged-actions.md`, не «секретным портом» вместо пароля.
3. Между сервисами явный список кто к кому ходит. Запрет по умолчанию, если это описывает код инфраструктуры.
4. Управление узлами только по шифрованному каналу.
5. Не считать сегмент доказательством личности. См. `microservices.md`.

## Промпт

```text
По файлам инфраструктуры проверь, какие порты открыты наружу.

Оставь снаружи только вход приложения и нужные вебхуки. Базу и админку не публикуй.
Секретный порт не считай паролем. Между сервисами не ставь «разрешить всё», если манифест это описывает.
Если сети в репозитории нет, напиши человеку, что проверить нечего в коде, и не сканируй боевые адреса.
```

## Готово, когда

- [ ] Пример прода не открывает базу наружу
- [ ] Админка не защищена только нестандартным портом
- [ ] В манифестах нет лишнего «разрешить всю внутреннюю сеть», либо это отмечено
- [ ] Боевая сеть не сканировалась
