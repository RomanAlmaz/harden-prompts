# Доступ к базе

Инъекция - отдельный файл. Здесь учётка, сеть, бэкап и права: даже верный запрос не должен идти от суперпользователя и наружу в интернет.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Приложение ходит владельцем сервера базы | Любая ошибка запроса читает и меняет всё |
| База опубликована в сеть | К ней подключаются помимо приложения |
| Бэкап без шифрования и без ограничения доступа | Утечка бэкапа равна утечке базы |
| Миграции и приложение делят одну учётку | Рабочий процесс может менять схему |
| В примере compose база без пароля на все интерфейсы | Пример копируют в бой |

## Сделать

1. Учётка приложения: только нужные таблицы и действия. Отдельная учётка миграций. Не суперпользователь.
2. База слушает внутреннюю сеть. В примерах для прода не публиковать порт наружу. См. `containers.md`.
3. Соединение приложения с базой шифровать, если сеть между ними не является осознанно изолированной. Проверку сертификата не отключать.
4. Бэкап шифровать средствами платформы и не класть в общий бакет. Если бэкап вне репозитория, пункт человеку.
5. Пароль базы - секрет. См. `09-data/secrets.md`. В лог запросов не писать значения параметров с секретами.

## Промпт

```text
Проверь доступ приложения к базе по файлам репозитория.

Сузь учётку приложения, если права задаются в миграциях или манифестах. Миграции отдели от учётки приложения.
Не публикуй порт базы в боевом примере. Не отключай проверку TLS к базе.
Пароль убери из кода. Бэкап, если его нет в репозитории, отдай человеку пунктом, не выдумывай, что он зашифрован.

Не подключайся к боевой базе и не выводи из неё строки.
```

## Готово, когда

- [ ] Приложение не описано как суперпользователь базы
- [ ] Боевой пример не выставляет порт базы в мир
- [ ] Пароль базы не в git
- [ ] Бэкап либо закрыт в файлах, либо честно отдан человеку
