# Состав поставки

Список компонентов нужен, чтобы понять, какая библиотека попала в сборку, когда по ней выходит сообщение об уязвимости. Список сам по себе дыру не закрывает.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Нет списка того, что уехало в прод | Нельзя быстро сказать, есть ли в сборке проблемная версия |
| Список собирают вручную и забывают транзитивные зависимости | В нём только прямые пакеты |
| Список считают заменой обновлений | Известная дыра остаётся |
| В список или в логи сборки попадают секреты | Инвентаризация становится утечкой |

## Сделать

1. В CI собирать машиночитаемый состав из lock-файла и артефакта, включая транзитивные зависимости. Формат платформы, обычно CycloneDX или SPDX.
2. Хранить состав рядом с версией сборки. Не подменять его ручным README.
3. Обновления по-прежнему по `dependencies.md`. Состав не отключает аудит.
4. В состав не писать значения секретов и переменные среды.

## Промпт

```text
Если в репозитории есть сборка релиза, добавь или почини машиночитаемый состав зависимостей из lock-файла.

Не заменяй этим обновление уязвимых пакетов. Не клади в состав секреты.
Если CI вне репозитория, опиши человеку, какой файл состава должен появиться у релиза, и не объявляй задачу сделанной.

Не подключай лишние сервисы публикации состава без спроса.
```

## Готово, когда

- [ ] Состав берётся из lock-файла, не из памяти
- [ ] Аудит зависимостей не выключен
- [ ] В составе нет секретов
- [ ] Если CI снаружи, это сказано прямо
