# Зависимости

Чужая библиотека выполняется как свой код. Обновление закрывает известные дыры. Слепое обновление мажорных версий без прогона тестов ломает продукт, поэтому чинить надо по риску, а не ритуалом.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Зависимости лет без обновления | Известные дыры остаются |
| Нет фиксации версий | Сборка завтра берёт другой код |
| Скрипты установки пакета бегут вслепую | Чужой пакет выполняется при install |
| Пакет никто не проверял, имя похоже на известное | В проект попадает не та библиотека |
| Игнорируются советы аудита пачками | Важные дыры тонут в шуме |
| Приватный реестр без аутентификации | Туда кладут подмену |

## Сделать

1. Включить штатный аудит менеджера пакетов в CI. Сначала закрыть критичные уязвимости, которые реально вызываются. Не «закрыть» отключением аудита.
2. Зафиксировать дерево зависимостей lock-файлом и коммитить его.
3. Обновления безопасности ставить отдельно от косметического апгрейда. Прогонять тесты проекта.
4. Убрать пакеты, которые не используются.
5. Не отключать проверку подписи и TLS у реестра.
6. Секреты не нужны для `npm install` публичных пакетов. Токен реестра - в CI-секретах, не в файле.
7. Если аудит требует мажор и это ломает API - оставить задачу человеку, не выключать предупреждение молча.

## Промпт

```text
Проверь зависимости проекта.

Не отключай аудит. Обнови пакеты с известными критичными дырами в рамках совместимых версий и прогони тесты.
Lock-файл должен быть в репозитории. Неиспользуемые прямые зависимости убери, если это не ломает сборку.
Токен реестра не клади в код.
Если правка требует мажорной миграции, опиши её человеку и не притворяйся, что дыра закрыта.

Не добавляй новые пакеты без нужды и не запускай пост-инсталл скрипты из непрошенных источников.
```

## Готово, когда

- [ ] Lock-файл на месте
- [ ] Аудит не выключен
- [ ] Совместимые критичные обновления поставлены или честно отложены
- [ ] Токена реестра нет в git
