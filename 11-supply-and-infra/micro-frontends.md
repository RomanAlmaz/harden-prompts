# Несколько фронтендов на одной странице

Кусок интерфейса с другого адреса выполняется в твоём origin, если его вставили скриптом. Общая cookie и общий `localStorage` тогда принадлежат и этому куску.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Чужой фрагмент подключают скриптом в тот же origin | Он читает то, что может скрипт страницы |
| Общий токен в `localStorage` | Любой фрагмент забирает сессию |
| Нет списка разрешённых адресов фрагментов | Подменяют источник скрипта |
| Фрагмент сам ходит в API правами человека без отдельной проверки | Сервер не отличает фрагмент от основного приложения, и это нормально только если права всё равно проверяются |

## Сделать

1. Не доверять фрагменту секрет. Сессия в `HttpOnly` cookie, не в общем хранилище скриптов. См. `02-session/session.md`.
2. Список адресов, откуда можно грузить фрагмент. CSP это закрепляет. См. `04-transport/csp.md`.
3. Версию чужого скрипта фиксировать, где это статический файл. См. `04-transport/third-party-scripts.md`.
4. API не даёт фрагменту больше прав, чем человеку. Проверка на сервере та же.
5. Если фрагменты должны быть изолированы, держать их на отдельных origin и общаться через `04-transport/postmessage.md`, а не через общие глобальные переменные.

## Промпт

```text
Если страница собирается из нескольких фронтендов, не отдавай им сессию через localStorage.

Оставь сессию в HttpOnly cookie. Зафиксируй список адресов фрагментов в CSP.
API проверяет права так же, как для основного клиента.
Изоляцию делай отдельным origin и проверкой postMessage, не общим глобальным объектом.

Если микрофронтендов нет - пропусти.
```

## Готово, когда

- [ ] Токен фрагмента не лежит в `localStorage`
- [ ] Адреса фрагментов ограничены
- [ ] Сервер не выдаёт лишних прав из-за того, что вызов пришёл из фрагмента
