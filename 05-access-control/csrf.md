# Подделка запроса с чужого сайта

Если браузер сам прикладывает cookie, чужой сайт может попросить браузер человека сделать действие на нашем сайте. Человек при этом просто открыл страницу.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Cookie-сессия и нет второго барьера на POST | Чужой сайт меняет почту, пароль или платёж |
| Защита есть у формы, но нет у JSON API с cookie | API остаётся годным для чужого сайта |
| Токен CSRF лежит в cookie и его же читают из cookie без сверки с заголовком | Барьер не отличается от обычной cookie |
| `SameSite` считают полной заменой токена | Новые сценарии навигации и старые клиенты оставляют дыры; OWASP не считает SameSite заменой токена |
| GET меняет данные | Ссылка и картинка запускают действие |
| Проверка только заголовка Origin, и при его отсутствии запрос пропускают | Запросы без заголовка проходят |

## Сделать

1. Все изменения состояния - не GET. GET ничего не меняет.
2. Для сессий на cookie: отдельный токен CSRF на сессию или на действие. Токен в форме или заголовке, сверка на сервере. Cookie, которую браузер приложит сам и которую сервер только читает обратно, токеном не считается.
3. `SameSite` оставить как второй слой, не как единственный. См. сессию.
4. У браузерных запросов с cookie, которые меняют данные, проверять `Origin` или `Referer`. Если обоих нет - отказ. Список хостов точный. Запрос без cookie, где доступ доказывает заголовок `Authorization`, этим правилом не отсекай.
5. API на bearer-токене, который скрипт ставит в заголовок сам, классической подделке с чужого сайта не подвержен. Не перекладывай этот токен в cookie без тех же проверок.
6. Вход, выход, смена почты, смена пароля и оплата покрыты тем же контролем.

## Промпт

```text
Закрой подделку межсайтового запроса для всех действий, где браузер сам прикладывает cookie.

Изменения состояния не должны выполняться через GET.
Добавь серверную проверку CSRF-токена или эквивалент фреймворка и не отключай её для JSON.
SameSite оставь, но не считай единственной защитой.
Для запросов с cookie требуй ожидаемый Origin либо Referer и отклоняй пустой.
Bearer, который скрипт кладёт в заголовок сам, не переноси в cookie без этой защиты.

Не пиши страницу, которая выполняет действие на чужом сайте. Если cookie-сессий нет - напиши это и проверь, что токен доступа не лежит в cookie, которую браузер прикладывает сам.
```

## Готово, когда

- [ ] Изменяющие запросы не висят на голом GET
- [ ] Cookie-действия требуют CSRF-барьер фреймворка
- [ ] Браузерный запрос с cookie без Origin и Referer не проходит
- [ ] Вход, выход, смена почты и оплата покрыты
