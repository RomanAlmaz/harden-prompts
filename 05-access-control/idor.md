# Доступ к чужому объекту по id

Угадываемый id в URL не проблема сам по себе. Проблема в том, что сервер отдаёт объект, не проверив владельца. Замена ключа на UUID это не лечит.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| `GET /orders/1001` без проверки владельца | Читаются и меняются чужие заказы |
| id пользователя в теле меняет «от чьего имени» | Действие выполняется за другого |
| Скрытый id в HTML считается секретом | Его видно в источнике страницы |
| UUID без проверки владельца | Адрес всё равно утекает в логе, письме и Referer |
| Вложенный id (`/users/1/invoices/2`) проверяет только первый | Второй принадлежит другому человеку |
| Экспорт, поиск и «поделиться» идут другим кодом без той же проверки | Дыра остаётся рядом с починенным CRUD |
| Ошибка 403 и 404 выбраны так, что палят существование | По ответу перечисляют чужие объекты. Для закрытых объектов чаще уместен один и тот же ответ, как для отсутствующих |

## Сделать

1. На чтении, записи, удалении и экспорте загружать объект и сверять владельца или членство в том же контуре доступа. Не строить запрос «дай мне id» без условия доступа.
2. id субъекта брать из сессии, не из тела.
3. Вложенные id проверять все: родитель и ребёнок связаны между собой и оба доступны этому субъекту.
4. Те же правила в поиске, подсказках, websocket, графиках и фоновой выгрузке.
5. Для объектов, о существовании которых посторонний не должен знать, отвечать так же, как если объекта нет.
6. Смена владельца и шаринг - отдельные права, не побочный эффект обычного update.

## Промпт

```text
Найди доступ к объектам по идентификатору: заказ, файл, профиль, счёт, сообщение, организация.

Каждая выборка и команда должна включать условие доступа на сервере. Не доверяй id пользователя из тела.
Проверь вложенные id, поиск, экспорт и сокеты тем же правилом.
Чужой и несуществующий закрытый объект не должен различаться ответом, если продукт не обязан показывать «доступ запрещён» осознанно.
Не заменяй проверку на «давайте сделаем UUID» как единственную меру.

Не перечисляй чужие id и не пиши перебор. В конце: какие модели закрыты, какие маршруты ещё сомнительны.
```

## Готово, когда

- [ ] Чужой id не отдаёт объект
- [ ] id субъекта берётся из сессии
- [ ] Вложенные ресурсы проверяются
- [ ] Экспорт и поиск не обходят ту же проверку
