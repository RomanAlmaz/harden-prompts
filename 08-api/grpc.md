# gRPC

Двоичный RPC - тот же API. TLS, права и лимиты не появляются оттого, что это не JSON. Клиенту нельзя верить полям «я админ» внутри сообщения.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Канал без TLS и без аутентификации сервиса | Кто в сети, тот зовёт методы |
| Право проверяют по полю в сообщении | Клиент ставит себе роль |
| Нет лимита размера сообщения | Одно сообщение забирает память |
| Отражение и отладочные сервисы включены | Видна вся схема и лишние методы |
| Ошибка возвращает внутренние детали | Видно устройство сервиса |

## Сделать

1. TLS между сервисами. Кто вызывает - проверять сертификатом, токеном или рабочей учётной записью платформы, не сетью «мы в одном кластере».
2. Каждый метод проверяет право на действие и объект. Роль не брать из тела запроса.
3. Лимит размера сообщения и крайний срок вызова.
4. Отладочное отражение схемы выключить на проде или закрыть доступом.
5. Ошибки наружу без стека и без секретов.

## Промпт

```text
Если есть gRPC, закрой канал, права и размер сообщений.

Включи TLS и аутентификацию вызывающего. Не доверяй роли в теле сообщения.
Поставь лимит размера и таймаут. Отладочное отражение на проде выключи или закрой.
Ошибки не должны содержать стек.

Если gRPC нет - не добавляй его. Не описывай разбор чужих сообщений.
```

## Готово, когда

- [ ] Канал шифруется, вызывающий известен
- [ ] Право не берётся из тела
- [ ] Есть лимит размера
- [ ] Отладка схемы не открыта на проде
