# WebSocket

Сокет после открытия живёт долго. Проверка только при загрузке страницы не спасает: сообщение внутри канала тоже должно нести право, а чужой origin не должен открывать сокет с cookie человека.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Origin сокета не проверен | Чужой сайт открывает канал с cookie |
| Подписка на канал по id без права | Слушают чужие события заказа или чата |
| Сообщение внутри сокета - команда без повторной проверки | Канал, открытый для чтения, начинает менять данные |
| Нет лимита сообщений | Один клиент забивает сервер |
| Токен в query сокета | Он оседает в логах прокси |
| Сервер шлёт событие всем в комнате, комната общая | Утечка между пользователями |

## Сделать

1. `wss`, не открытый `ws`, для всего, где есть сессия.
2. Проверять Origin по белому списку. Сессию проверять при рукопожатии.
3. Каждая подписка и каждая команда проверяют право на объект. Id комнаты не является секретом.
4. Лимит размера и частоты сообщений. Таймаут неактивного сокета.
5. Не передавать сессионный токен в URL.
6. Не слать в событии лишние поля чужих пользователей.

## Промпт

```text
Проверь WebSocket или аналог.

Рукопожатие только по wss, с проверкой Origin и сессии. Токен не ставь в query.
Каждая подписка и команда проверяет право на объект. Чужие комнаты не слушать.
Поставь лимит частоты и размера. События не должны содержать лишние персональные поля.

Если сокетов нет - пропусти. Не пиши перехват чужого канала.
```

## Готово, когда

- [ ] Origin и сессия проверяются при открытии
- [ ] Подписка на объект проверяет право
- [ ] Есть лимит сообщений
- [ ] Токен не в URL
