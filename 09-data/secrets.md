# Секреты и ключи

Секрет в репозитории, в образе контейнера и в фронтенде уже скомпрометирован, даже если репозиторий «пока приватный». Ротация после утечки обязательна: удалить файл из git мало.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Ключ в коде, `.env` в git, в тикете или в примере, который на самом деле боевой | Ключ живёт в истории навсегда |
| Секрет вшит в мобильное или браузерное приложение | Его достают из клиента |
| Один ключ на тест и прод | Утечка теста бьёт по боевым данным |
| Лог и ошибка печатают конфиг целиком | Секрет уходит в систему логов |
| Нет ротации | Старый сотрудник и старый бэкап знают ключ |
| `.env.example` заполнен живыми значениями | Пример становится утечкой |

## Сделать

1. Секреты - в хранилище среды или секрет-менеджере. В git только пример с пустыми или явными фейковыми значениями.
2. Найти уже закоммиченное и убрать из дерева. Считать секрет скомпрометированным: человек должен отозвать его у поставщика. Не переписывать историю втихомолку и не класть секрет в отчёт.
3. Разные секреты у теста и прода. Минимальные права у каждого ключа.
4. Логгер редактирует поля `password`, `secret`, `token`, `authorization`, `cookie`, `pan`, `cvv`.
5. Клиентскому приложению не давать секрет, которым можно действовать от имени сервиса.
6. Добавить проверку в CI, что типичные ключи не появляются в diff. Проверка не должна печатать сам секрет.

## Промпт

```text
Найди секреты в репозитории, примерах, клиентском коде и логах.

Убери их из дерева и из .env.example, подставь пустые плейсхолдеры. Не вставляй найденные значения в отчёт: только файл и имя переменной.
Пометь, что человек обязан отозвать ключ у поставщика, потому что история git его помнит.
Проверь, что приложение читает секрет из окружения, а логгер режет известные секретные поля.
Добавь или включи секрет-скан в CI без печати находок.

Не открывай боевые кабинеты и не проверяй, «работает ли ещё ключ», боем по чужому API.
```

## Готово, когда

- [ ] В дереве git нет боевых секретов и не добавлены новые
- [ ] Пример конфига пустой
- [ ] Логи не печатают секреты
- [ ] Найденные ключи помечены на отзыв человеком
- [ ] Клиент не содержит серверный секрет
