# Шифрование данных в покое

Шифрование уменьшает ущерб от унесённого диска и бэкапа. Оно не спасает, если приложение само расшифровывает всё подряд, а ключ лежит в той же базе. Пароли не шифруют, их хешируют.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Свой шифр, ECB или повтор nonce | Повтор nonce у AES-GCM раскрывает данные и ломает проверку подлинности |
| Ключ в той же таблице, что данные | Утечка читается сразу |
| Бэкап без шифрования рядом с зашифрованной базой | Уносят бэкап |
| Шифруют всё подряд, включая то, по чему ищут, и отключают контроль доступа | Шифрование подменяет собой права |
| В лог пишут открытый текст «для отладки» | Журнал становится копией данных |

## Сделать

1. Библиотека платформы. Для нового симметричного шифрования - AEAD вроде AES-GCM или ChaCha20-Poly1305. Nonce уникальный на каждое сообщение, криптостойкий, не счётчик, который может повториться. Не ECB, не самодельный XOR, не MD5 как ключ.
2. Ключ - в секрет-менеджере или KMS, не в репозитории и не рядом с данными. Ротация описана.
3. Шифровать то, что правда секретно в покое: токены обновления в базе, секреты TOTP, документы, если продукт их хранит. Пароли - только медленный хеш.
4. Диски и бэкапы: шифрование средствами платформы, если это есть в инфраструктуре. Если настройки вне репозитория - пункт человеку.
5. Не логировать открытый текст. Поиск и права работают до того, как данные показали.
6. Не обещать «соответствие закону о персональных данных» одним фактом шифрования.

## Промпт

```text
Проверь шифрование данных в покое. Не пиши свой шифр.

Секреты в базе, которые не являются паролем пользователя, шифруй штатным AEAD, ключ вне базы и вне git. Nonce не повторяй.
Пароли оставь на медленном хеше, не на шифровании.
Убери открытый текст этих секретов из логов.
Если бэкапы настраиваются вне репозитория, добавь пункт в отчёт человеку, не выдумывай, что они уже закрыты.

Не выводи расшифрованные боевые данные в отчёт.
```

## Готово, когда

- [ ] Нет самодельного шифра
- [ ] Ключ не лежит рядом с данными и не в git
- [ ] Пароли хешируются, а не шифруются
- [ ] Бэкапы упомянуты честно: сделано или отдано человеку
