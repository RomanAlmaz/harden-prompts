# Ошибки наружу

Подробная ошибка помогает разработчику и постороннему. Наружу нужен корреляционный id и общий текст. Подробности остаются в журнале.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Стек, SQL и путь сервера в JSON | Видно устройство и запрос |
| Режим отладки на проде | Страницы ошибок показывают переменные и секреты |
| Разная ошибка для «нет объекта» и «нет прав» там, где объект скрытый | Перечисляются id |
| Ошибка провайдера оплаты проксируется как есть | В ней лишние данные |
| Пользователю показывают внутреннее исключение | Иногда в тексте оказывается кусок данных |

## Сделать

1. Единый обработчик: человеку код и короткое сообщение, в лог - исключение и id события.
2. Выключить debug на проде конфигом, который прод не переключает одним query-параметром.
3. Не отражать обратно тело запроса с полями секретов.
4. Для скрытых объектов выбрать одну политику ответа и держать её. См. `idor.md`.
5. Страницы 4xx и 5xx без версии фреймворка и без подсказки «попробуй такой-то путь админки».
6. Если при ошибке действие всё равно выполняется, это не этот файл, а `exceptional-conditions.md`: сбой проверки должен останавливать запрос.

## Промпт

```text
Сделай так, чтобы наружу не уходили стек, SQL, пути сервера и секреты.

Один обработчик ошибок, корреляционный id, подробности только в логе.
Выключи debug в проде. Не отражай сырое тело запроса в ошибке.
Не добавляй в сообщение ошибки советы, как обойти проверку.
```

## Готово, когда

- [ ] Ответ ошибки без стека и без SQL
- [ ] Прод не в debug
- [ ] Есть id события, по которому ищут лог
- [ ] Секрет из запроса не отражается
