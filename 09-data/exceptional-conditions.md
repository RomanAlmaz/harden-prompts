# Сбой и отказ в безопасную сторону

Если проверка права, платежа или подписи падает с ошибкой, действие надо остановить. Продолжить «как будто проверки не было» - это открытый отказ. Незаконченный перевод денег надо откатить целиком.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Исключение в проверке прав ловится и запрос идёт дальше | Сбой авторизации пускает действие |
| Нет параметра, и код подставляет права администратора или пустой фильтр | Отсутствие поля снимает ограничение |
| Деньги списались, зачисление упало, отката нет | Средства теряются или удваиваются |
| Ресурс при ошибке загрузки не отпускается | Повторы забивают память и соединения |
| У каждого модуля свой глушитель ошибок | Одни пути молчат, другие открывают доступ |
| Подробности сбоя уходят клиенту | Это уже `errors.md` |

## Сделать

1. Ошибка проверки аутентификации, авторизации, подписи и схемы входа останавливает действие. По умолчанию отказ.
2. Нет обязательного поля - отказ, не значение по умолчанию с максимальными правами и не пустое условие «все строки».
3. Несколько записей денег и остатков - одна транзакция. Исключение откатывает её. Не чинить наполовину.
4. Файлы, соединения и блокировки закрывать и при ошибке.
5. Один общий обработчик на границе запроса плюс явная обработка там, где есть транзакция. Пустой `catch`, который ничего не делает, убрать с путей безопасности.
6. Повтор одной и той же ошибки ограничивать. См. `08-api/rate-limit.md`. Журнал без секретов. См. `logging.md`.

## Промпт

```text
Найди места, где ошибка проверки или нехватка данных не останавливает действие.

Сбой авторизации, подписи и валидации должен отказывать. Отсутствующее поле не должно становиться полными правами или пустым фильтром.
Платежи и остатки проводи одной транзакцией с откатом.
Закрывай ресурсы в ошибке. Убери пустые catch на этих путях.
Наружу по-прежнему не отдавай стек. Это не отменяет остановку действия.

Не описывай, как довести проверку до исключения. Если поведения продукта при сбое платежа неясно - спроси, не выбирай молча.
```

## Готово, когда

- [ ] Ошибка проверки не пускает действие дальше
- [ ] Нет обязательного поля значит отказ
- [ ] Денежная операция откатывается целиком
- [ ] Пустой catch не стоит на пути прав и платежей
