# Сессия и cookie

Сессия - пропуск после входа. Если id угадывается, светится в скрипте или уходит по HTTP, пароль уже не нужен.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Id сессии короткий или из счётчика | Чужой пропуск подбирают |
| Нет `Secure` | Браузер отдаёт cookie по HTTP, если его туда заманить |
| Нет `HttpOnly` | Скрипт на странице читает пропуск |
| `SameSite` не задан | Cookie уходит на чужие сайты шире, чем нужно |
| Id в URL | Утекает через Referer, историю и логи |
| Сессия в `localStorage` | Любой XSS забирает её насовсем |
| Сырой id в базе | Кто прочитал таблицу сессий, входит как эти люди |
| Нет простоя и абсолютного срока | Украденный пропуск живёт, пока человек когда-то логинился |

## Сделать

1. Id из CSPRNG, энтропия не ниже 64 бит, цель от 128. Не кодировать в id роль, почту и права. Не использовать последовательные числа.
2. Cookie: `Secure`, `HttpOnly`, `SameSite=Strict` или осознанный `Lax`, `Path=/`. Предпочтительно имя `__Host-` без `Domain`. `SameSite=None` только вместе с `Secure` и только если кросс-сайт реально нужен.
3. Не передавать id в query. Не класть его в `localStorage` и `sessionStorage`.
4. В хранилище сессий по возможности писать хеш id. Срок простоя задать по риску: минуты для денег и админки, дольше для низкого риска. Абсолютный срок - всегда, даже если вкладка активна. Ориентиры OWASP: простой 2-5 минут для ценных приложений и 15-30 для низкого риска; абсолютный срок под реальное использование, не «вечность».
5. Смена привилегии (вход, смена пароля, повышение роли) меняет id и гасит старый.
6. Выход удаляет сессию на сервере, а не только cookie в браузере.
7. Привязка к IP целиком часто ломает мобильных людей. Не включать её молча. Если нужен сигнал смены сети - переспросить вход, а не тихо отказать всем.

## Промпт

```text
Приведи сессии к серверному пропуску, который нельзя угадать и нельзя прочитать скриптом.

Сделай:
- id из CSPRNG, от 64 бит энтропии, лучше от 128, без роли и почты внутри;
- cookie Secure, HttpOnly, явный SameSite, Path=/; для основной сессии префикс __Host- и без Domain;
- id не в URL и не в localStorage;
- в базе лучше хеш id, плюс простой и абсолютный срок жизни;
- новый id после входа и после повышения прав;
- выход удаляет сессию на сервере.

Не пиши подбор id и перехват cookie. Если сессия уже в фреймворке - настрой его, не пиши свой менеджер.
```

## Готово, когда

- [ ] Id непредсказуемый и не в URL
- [ ] Стоят `Secure`, `HttpOnly`, явный `SameSite`
- [ ] Есть простой и абсолютный срок
- [ ] Выход и смена прав гасят старый id
- [ ] Сессии нет в `localStorage`
