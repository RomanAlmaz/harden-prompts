# JWT и свои токены

Подписанный токен - не сессия, пока сервер не проверил подпись, адресата и срок. Токен, который нельзя отозвать, плох для входа в банк и админку.

Защитный промпт: имена угроз здесь, чтобы их закрыть. Пошаговых атак нет.

## Уязвимости

| Угроза | Что происходит |
| --- | --- |
| Алгоритм берётся из заголовка токена | Подпись отключают или подменяют ключ |
| Секрет подписи слабый или в репозитории | Кто угодно выпускает годные токены |
| Нет проверки `iss`, `aud`, `exp` | Чужой или просроченный токен принимают |
| В токене роль, и сервер верит ей без сверки | Человек навсегда остаётся админом внутри старого токена |
| Access token живёт дни | Кражу нельзя быстро погасить |
| Refresh в `localStorage` | Скрипт обновляет сессию сам |
| Нет разницы access и refresh | Украденный короткоживущий токен меняют на новый бесконечно |
| `none` или путаница ключей | Токен без настоящей подписи проходит |

## Сделать

1. Библиотека JWT. Алгоритм задан в конфиге сервера: для общего секрета не слабее HS256, лучше асимметрия вроде EdDSA или ES256, если ключи уже есть. Заголовок токена алгоритм не выбирает. `none` запрещён.
2. Проверять подпись, `exp`, `nbf` если есть, `iss`, `aud`. Допуск по времени - секунды, не часы.
3. Ключ - из хранилища секретов. Для HS256 секрет не короче 32 байт. Разные ключи у разных сред и сервисов. Ротация заложена.
4. В токен класть минимум: id субъекта, срок, издатель, адресат, версия прав или `jti`. Не класть пароль, почту без нужды, полные персональные данные.
5. Короткий access (минуты) и отдельный refresh. Refresh хранить сервером так, чтобы его можно было отозвать: хеш в базе, семья токенов, повторное использование старого refresh гасит всю семью.
6. Браузер: refresh в `HttpOnly` cookie, не в `localStorage`. Если API чистое и без cookie, описать, почему XSS в этом клиенте не читает токен. Для сайта предпочтительна своя сессия, а не JWT в JS.
7. Смена пароля, выход, бан - гасят refresh. Access умрёт по сроку; для админки либо короткий срок, либо список отзыва.
8. Не принимать токен из query.

## Промпт

```text
Проверь выпуск и приём JWT и похожих непрозрачных токенов.

Зафиксируй алгоритм на сервере, запрети none и выбор алгоритма из токена.
Проверяй подпись, exp, iss и aud библиотекой.
Секрет убери из кода. Для HS256 секрет не короче 32 байт. Access сделай коротким. Refresh должен отзываться на сервере и храниться не в localStorage.
Выход, смена пароля и бан гасят refresh.
Не клади в токен лишние персональные данные и не читай роль из токена, если права уже отозваны, а срок ещё длинный: либо сократи срок, либо сверяй версию прав.
Токен не принимай из query и не логируй.

Не пиши подделку токена. Если JWT нет - не вводи его ради этой задачи, оставь серверную сессию.
```

## Готово, когда

- [ ] Алгоритм и ключ задаёт сервер
- [ ] Проверяются подпись, срок, iss и aud
- [ ] Refresh можно отозвать
- [ ] Токена нет в `localStorage` и в логах
- [ ] Выход и смена пароля гасят обновление сессии
